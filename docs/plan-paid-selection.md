# 付费模型勾选与版本显示：决策记录

> **状态：已实施（2026-11-08）。** 本文保留「为什么这么设计」与「被否决的方案」，不再作为施工单。
> 代码为准；文中不含行号（原计划的 24 项清单与实施顺序已删除）。样例数据会随时间变化，判定的**规则**不变。
>
> 范围：TUI（`src/tui/**`）+ 共享层 `src/access.js` / `src/api.js` / `src/i18n/**`。
> CLI 与 WebUI 行为未变（CLI 仍用 `buildPlan()` 的登记版本语义）。

---

## 1. 三个症状与三个原因

| 症状 | 原因 | 落点 |
|---|---|---|
| 搜索页没勾，进版本页却显示最新版已勾 | ① 版本页自己补勾光标行；② 打开时不看搜索页的勾选状态；③ 返回时无条件勾选 | `ui/versionPage.js`、`flows/download.js` 的 `openRow`、`ui/planWorkspace.js` |
| 既有免费又有付费的模型显示 `[付费]`，且被默认勾选 | ① 徽标只看「有没有付费版本」；② 单模型入口用 `selectRestricted` 短路了默认勾选判断 | `flows/download.js` 的 `groupPlanRows`、`flows/models.js`、`ui/accessText.js` |
| 搜索页看不到已选版本 | `groupPlanRows` 重写 `detail` 时把版本名挤出了第一位 | `flows/download.js` 的 `groupPlanRows` |

三个问题互相独立，但**修法有顺序**：勾选同步不通，后面的默认勾选看起来就像没生效。

---

## 2. 核心概念：一行有两种「付费状态」

这是全文最容易看错的地方，也是所有规则的出发点。

| 字段 | 回答的问题 | 谁消费 |
|---|---|---|
| `access.requiresEntitlement`（行级） | 这一行**有没有**付费/限时版本 | 徽标、`p` 筛选、「含付费」提示 |
| `access.defaultSelected`（行级） | 这一行**默认要下的那个版本**是不是免费 | 复选框初始状态 |
| `accessCounts`（行级） | 该行已知版本按类型的计数 | 目前只用于诊断与测试（无生产读取方） |

**结论：徽标与默认勾选是两件独立的事。**

- 「5 版里 2 付费 3 免费、最新版付费」→ 徽标 `[付费/免费]`，默认**不勾**。
- 「5 版里 2 付费 3 免费、最新版免费」→ 徽标 `[付费/免费]`，默认**勾选**。
- 用户把本行改成某个免费旧版 → 徽标仍是 `[付费/免费]`，这一行在下载免费版本。

所以 `[付费/免费]` + 已勾选是**合法且常见**的组合，不是 bug。

> 实现口径：`defaultSelected = !defaultVersion.access.requiresEntitlement`，
> 其中 `defaultVersion = group.versions[0]`（本行的默认版本）。
> `mixed` 只进 `accessLabel()`，**不得**参与勾选判断。

## 3. 判定规则（不可动摇）

### 3.1 行徽标

按「该行已知的全部版本」汇总（`summarizeAccess()`）：

| 构成 | 徽标 |
|---|---|
| 全免费 | 不显示（保持视觉安静） |
| 全付费 | `[付费]` |
| 付费 + 免费 | `[付费/免费]` |
| 纯限时 | `[限时访问]` |
| 限时 + 免费 | `[限时访问/免费]` |

`summarizeAccess(list)` 返回 `{ total, free, paid, early, unavailable, restricted, mixed }`：
`restricted = paid + early`；`mixed = restricted > 0 && free > 0`；`public` 与「付费期已结束」都算 `free`。

### 3.2 版本名后缀

只在「行徽标无法说明该版本」时出现：

| 行徽标 | 版本自身 | 后缀 | 效果 |
|---|---|---|---|
| 无（全免费） | 免费 | 不带 | `v1.0` |
| `[付费]`（全付费） | 付费 | 不带 | `[付费] Base_V2` |
| `[付费/免费]` | 付费 | **带** | `[付费/免费] Base_V2（付费）` |
| `[付费/免费]` | 免费 | 不带 | `Base_V2（付费）/SFT_V1` |
| `[付费/免费]` | 限时付费 | **带（含截止日期）** | `xxx（付费至 2026-11-15）` |

判据是 `counts.mixed === true`：纯付费/纯免费的行，徽标已经说明整行状态，再给每个版本加「（付费）」只会白占右列宽度。

### 3.3 默认勾选

| 本行默认版本 | 徽标 | 默认勾选 |
|---|---|---|
| 免费 | 无 或 `[付费/免费]` | 勾选 |
| 付费 | `[付费]` 或 `[付费/免费]` | 不勾 |
| 限时 | `[限时访问]` 或 `[限时访问/免费]` | 不勾 |
| 不可下载 | `[不可下载]` | 不勾（版本页也禁止勾选） |

`defaultSelected` 只在**建计划时**消费（`runDownloadWorkspace` 的初始选择、`planWorkspace.resolveInput` 新增行）；用户手动改过之后不会再套用默认值，不会把用户的选择「抢回去」。

### 3.4 默认版本 = 发布时间最新

`最新 = modelVersions 里 publishedAt 最大的版本；并列时比 createdAt，再比版本 id`。

理由：**数组顺序是站点的排序习惯，不是契约**。案例 2 的孪生版本只差 7 分钟，接口把免费版（08:54）排在付费 BF16（09:01）前面——「取数组第一个」与「按时间取最新」在该模型上会选出不同版本。

| 场景 | 默认版本 |
|---|---|
| 模型入口，粘贴模型 ID/URL | 发布时间最新的版本 |
| 模型入口，粘贴 `version:<id>` | 那个版本（用户明确指定） |
| 任何入口，模型库固定过版本 | 固定版本（优先级高于「最新」） |
| 收藏集入口 | 该成员模型的**最新版本**（不再用登记的版本） |

### 3.5 版本页排序与光标

`versionRows()` 按 `publishedAt` 倒序，行 0 即默认版本。

| 进入时的行状态 | 光标 |
|---|---|
| 未勾选 | 第 0 行（最新版本），按一次空格即可勾上 |
| 已有勾选 | 排序后**第一个**被勾选的版本 |

不用「永远第一行」是因为：重新打开页面时用户最想确认「我上次选了什么」；从已选版本出发去浏览相邻版本，比先滚到勾选行再调整更符合心智。对「未勾选」的行两种规则完全一样，而「未勾选」才是最常见的进入原因。

### 3.6 多基础模型

| 位置 | 规则 |
|---|---|
| `groupPlanRows` | `baseModels` = 该行所有版本去重后的基础模型；`baseModel = baseModels.join(' / ')` 仅用于显示 |
| 搜索页 | 一个 → 原样；多个 → `MOSS Image / Krea 2` |
| `b` 筛选候选值 | 从所有行的 `baseModels` 展开收集，不是从连接后的字符串切 |
| `b` 筛选匹配 | 行的 `baseModels` **包含**所选值即命中（两种取值下该行都出现） |
| 版本页 / 确认页 | 行是单个版本，各自显示自己的基础模型，无需改 |

边界：某版本 `baseModel` 为空 → 不进列表；列表为空 → 行上不显示基础模型。
「Krea2」与「Krea 2」的空格差异来自站点数据本身，按原样显示/匹配，不做归一化。

### 3.7 勾选契约（三处必须一起改）

| 搜索页这一行 | 版本页初始状态 | 版本页按 Enter 后 |
|---|---|---|
| `[✓]` | 计划里的版本全部勾选 | 勾了哪些就更新为哪些；全不勾 → 搜索页变 `[ ]` |
| `[ ]` | **一个都不勾**，光标停在默认版本上 | 勾了哪些 → 搜索页变 `[✓]` |
| 任意 | 按 Esc | 什么都不改 |

一句话：**搜索页的勾 = 这一行「有版本被选中」；版本页的勾 = 具体哪几个版本被选中。** 同一个事实的两个视角。

必须同时改三处，否则互相抵消：

- 只删版本页的自动补勾 → 未勾选的行进去仍显示已勾（`openRow` 还在传 `currentIds`）。
- 只改 `openRow` 传参 → 用户清空后又被补勾逻辑加回来，永远退不出勾选。
- 再改 `planWorkspace` 的返回处理 → `rows` 为空时 `splice(index, 1, ...[])` 会把整行删掉，模型凭空消失。

最终语义：

- **全不勾 + Enter = 取消这一行**：行保留、复选框变 `[ ]`，之后还能再进去勾。
- **Esc = 放弃本次修改**：保持进页面之前的状态。
- 两者不混淆，这就是 `Enter` 允许空数组、并删掉「尚未选择版本」提示的原因。

## 4. 证据：`paidAccess` 的真实形态

**已实测：`/api/v1/models/:id` 的 `modelVersions[]` 直接带 `paidAccess`**，无需额外请求版本接口。

| 版本情况 | 原始数据 |
|---|---|
| 免费 | **没有** `paidAccess` 字段（字段缺失，不是 `null`） |
| 永久付费 | `paidAccess: { permanent: true, endsAt: null }` |
| 限时付费 | `paidAccess: { permanent: false, endsAt: "2026-11-15T03:10:19.433Z" }` |
| 不能用来判免费 | `availability: "Public"`、`status: "Published"`（免费版本也有） |
| 未发布 / 禁止下载 | `status !== "Published"` 或 `usageControl !== "Download"` |

`classifyVersionAccess()` 的判定顺序：先 `paidAccess`，再 `status`/`usageControl`，最后 `availability`。付费判断**只用版本级字段**，经该函数。

**模型级 `hasActivePaidAccess` 不足以做任何勾选/徽标决策**：

| 模型 | 实际情况 | `hasActivePaidAccess` |
|---|---|---|
| 3007871 | 5 免费 + 4 付费（混合） | `true` |
| 3032176 | 2 个全付费 | `true` |

两种完全不同的构成，模型级标记都是 `true`。它只能回答「有没有付费版本」，回答不了「是不是混合」，也回答不了「默认版本是不是付费」。

## 5. 五个真实模型（验收基准）

> 撰写时实测；版本数与名称会随站点变化。验收时以当时接口返回为准，**规则**不变。

### 案例 1：`models/3008033` — 4 版（2 免费 + 2 付费），最新是免费的

| 版本 id | 名称 | 发布时间 | `paidAccess` | 分类 |
|---|---|---|---|---|
| 3456657 | MIX_V2 | 撰写当日 | 无 | 免费 |
| 3443533 | Base_V2 | 11-01 | `permanent:true` | 付费 |
| 3435059 | SFT_V2 | 10-28 | `permanent:true` | 付费 |
| 3413227 | SFT_V1 | 10-18 | 无 | 免费 |

预期：`restricted=2, free=2` → `[付费/免费]`；默认版本 MIX_V2（免费）→ **勾选**；版本名 `MIX_V2`（无后缀）。

### 案例 2：`models/3007871` — 混合，付费的都是 BF16 版

| 版本 id | 名称 | 发布时间 | 分类 |
|---|---|---|---|
| 3449754 | V4.1 25STEPS CFG3 | 11-04 08:54 | 免费 |
| 3449755 | V4.1 25STEPS CFG3 BF16 | 11-04 09:01 | 付费 |
| 3435978 / 3436014 | V3.3 … / … BF16 | 10-29 | 免费 / 付费 |
| 3423810 / 3423813 | V2.0 … / … BF16 | 10-23 | 免费 / 付费 |
| 3414956 / 3414867 | V1.0 … / … BF16 | 10-19 | 免费 / 付费 |
| 3413141 | V1.0 Turbo BF16 | 10-18 | 免费 |

预期：`[付费/免费]`；默认版本是 BF16（09:01，付费，比免费版晚 7 分钟）→ **不勾**；版本名 `V4.1 25STEPS CFG3 BF16（付费）`。

**这是「数组第一个 ≠ 发布时间最大」的实证**，也是 3.4 的直接依据。

### 案例 3：`models/3013038` — 2 版全付费，且基础模型不同

| 版本 id | 名称 | 发布时间 | Base Model | 分类 |
|---|---|---|---|---|
| 3426256 | MOSS Image | 10-24 | MOSS Image | 付费 |
| 3419799 | Krea2 | 10-21 | Krea 2 | 付费 |

预期：纯付费 → `[付费]`，默认**不勾**，版本名**不带**后缀。
两个版本都勾上后行显示 `MOSS Image/Krea2 · MOSS Image / Krea 2`，`b` 筛选两种取值都命中（3.6）。

### 案例 4：`models/3032176` — 2 版全付费

| 版本 id | 名称 | 发布时间 |
|---|---|---|
| 3446992 | Vellus HairPeach FuzzMOSS | 11-02 |
| 3444830 | Vellus Hair Peach Fuzz K2 | 11-01 |

预期：`[付费]`，默认**不勾**。
模型级 `hasActivePaidAccess: true`，但这条不足以判断混合——仍需逐版本看。

### 案例 5：`models/3017010` — 1 限时付费 + 1 免费

| 版本 id | 名称 | 发布时间 | `paidAccess` |
|---|---|---|---|
| 3440660 | MOSS_ultimate reborn_INT8 | 10-31 | `permanent:false, endsAt:2026-11-15` |
| 3424997 | v1.0 | 10-23 | 无 |

预期：`[付费/免费]`（汇总徽标不带日期）；版本名保留日期 `MOSS_ultimate reborn_INT8（付费至 2026-11-15）`；默认**不勾**。

**11-15 之后自动变化**：`endsAt` 过期 → `reason: paid-expired`、`requiresEntitlement: false` → 整行变全免费 → 徽标消失、默认**勾选**。不需要改配置，只看当前时间。

## 6. 收藏集入口统一与缓存

**语义变化**：收藏集成员的默认下载版本，从「收藏集登记的版本」改为「该模型最新版本」，固定版本仍优先。

**实现**：每成员的元数据请求从 `/api/v1/model-versions/:id`（只拿登记版本）换成 `/api/v1/models/:id`（模型 + 全部版本 + 文件清单）。

- **请求数不变**：每成员仍是 1 次，只是响应更大（含图片/描述）。换来收藏集行也有完整徽标 + 默认最新版本。
- **快照语义不变**：`writeCollection` 仍记录枚举到的成员与登记版本；「计划用什么版本」与「快照记了什么」从此可能不同。
- **登记版本已被删除的成员**：直接按最新版本下载（快照仍保留旧记录），这正是「跟随最新」的期望行为。
- **错误处理不变**：成员详情拉取失败 → 该项带 `error`，不进计划。

`buildPlanFromModels(site, items, userAgent, opts)` 与 `buildPlan()` 同构：

```
opts:  { concurrency, fileTypes, primaryOnly, entries, onLog, onProgress }
       entries = readLibrary().entries，用于固定版本判断
返回:  { plan, totalBytes, failed }

每成员：
  detail  = fetchModelDetail(site, item.modelId)          ← 命中缓存
  pinned  = entries[item.modelId].pinnedVersionId
  version = pinned ? find(pinned) ?? latest : latest
  item    = versionToItem(..., { model: detail })
            + { modelId, name, type, baseModel, modelMeta, modelAccess }
  失败 / 无文件 → { ...item, error }
日志复用 api.itemFiles / api.metaFailedLine
```

**会话缓存**（`fetchModelDetail`）：

| 项 | 取值 |
|---|---|
| 键 | `${site}|${modelId}` |
| 容量 | LRU 300 条（超出淘汰最久未用） |
| 新鲜度 | TTL 10 分钟 |
| 清理 | `clearModelDetailCache()`（测试 / 重新加载） |
| 不缓存 | `/api/v1/model-versions/:id` |

收益：模型入口「加行 → 进版本页」第 2 次请求命中缓存 → 0 次额外请求；收藏集入口进任何成员的版本页也是 0 次（原来每成员 1 次）。

## 7. 被否决的方案（防重犯）

| 方案 | 为什么否决 |
|---|---|
| 「只拉第一个版本以省请求」 | 模型详情一次响应就带全部版本，请求数恒为 1；要单独拉版本反而多一跳。省下的是本地几次对象遍历（微秒级），不值得加分支 |
| 用模型级 `hasActivePaidAccess` 做勾选/徽标 | 它只回答「有没有付费版本」，答不了「是不是混合」，更答不了「默认版本是否付费」（见 §4 的两行反例） |
| 把 `mixed` 用在默认勾选上 | 会让「最新版免费、另有付费版本」的模型被拦掉默认勾选；也会让「最新版付费」被误勾（§2） |
| 「永远第一行」的光标规则 | 有勾选时用户最想确认「我上次选了什么」，第一行给不出答案（3.5） |
| 只改三处中的一处来修勾选同步 | 见 3.7 的三种反例，单改任何一处都会互相抵消，甚至让整行消失 |
| 依赖 `modelVersions[0]` 当最新版本 | 数组顺序是站点习惯，案例 2 的孪生版本相差 7 分钟且顺序与时间不一致（3.4） |
| 在 `describeVersion` 里去掉 access 来消除重复徽标 | `downloadVersions()` 用的是通用选择器 `prompts.pickMany`，那里没有徽标列，去掉就没提示了。改为版本页判断「描述里已含该标签就不再追加」 |
| 用 `availability` / `status: Published` 判断免费 | 免费版本同样带这两个字段，判断不出付费 |

## 8. 已知代价与边界

| 项 | 说明 | 处理 |
|---|---|---|
| 孪生版本会落在付费版 | 同批发布、相差 7 分钟 → 按严格「最新」默认不勾 | 接受。若要「同批优先免费」，需另加「相差 1 小时内算同批」的容差，**未做** |
| 收藏集语义变化（大） | 作者发布新版本后，下次下载会拿到新版本而不是登记时的版本 | 固定版本仍优先；文档已写明；这是「跟随最新」的既定语义 |
| 请求体变大 | 每成员从版本接口换模型接口，带宽上升（请求数不变） | 接受；缓存只增用不增载 |
| 缓存新鲜度 | 会话内 10 分钟内看不到站点更新 | TTL 足够小；必要时 `clearModelDetailCache()` |
| 缓存内存 | 单条约 0.1~0.5 MB，300 条约 30~150 MB | 上限可降到 100 条，不影响正确性 |
| 行宽 | `[付费/免费]` 比 `[付费]` 宽 4 列 | 版本名放 detail 第一位 + 后缀规则；`rowLine()` 从尾部截断 |

**明确不做**：

- 不改 WebUI（`src/webui/**`）与 CLI 的付费策略；CLI 的收藏集计划仍走 `buildPlan()`（登记版本语义）。
- 不判断「当前账号是否已购买」（公开 API 不提供，不能猜）。
- 不改 `versionSelectionPage`（本地版本管理是「保留/删除」语义，与下载计划无关）。
- 不做「同批孪生版本优先免费」的容差。
- 不为徽标给收藏集做 N+1 请求（改为换端点，每成员仍是 1 次）。

## 9. 长期约束（仍然适用）

1. **i18n 三条**（`tests/i18n-tui.test.js` 逐条检查）：中英两份同时存在且英文不含中文；每个 `tui.*` 键必须在 `src/tui/**` 被引用；键名为 `tui.<模块>.<场景>`，模块在白名单内（`access` / `workspace` 均在）。
2. **`tui.hint.*` 必须单行**（`scripts/check-tui-contracts.js`）。
3. **流程代码不得接管终端**：`flows/**` 里不得出现 `console.log` / `process.stdout.write`，输出走 `view.log` / `view.notice`。
4. **付费判断只用版本级字段**（`paidAccess` / `status` / `usageControl` / `availability`，经 `classifyVersionAccess`）。
5. **纯逻辑放对地方**：分类与汇总放 `src/access.js`（可单测、三入口共用）；TUI 只做展示与交互。
