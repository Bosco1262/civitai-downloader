# TUI 设计规范（Phase 0 目标稿）

本文档定义 TUI 的目标设计语言。Phase 0 只写规范；Phase 1–5 分批迁移。
规范中的“必须”表示后续契约脚本会检查，“建议”表示评审约定。

## 1. 设计语言一句话

**骨架统一、页面语法统一、组件变体有限。**

- 骨架：页眉、仪表盘、面包屑、主体、页脚，由外壳强制。
- 页面语法：摘要 → 分区 → 操作；标题只在面包屑，正文不再重复。
- 组件变体：菜单/表单一种，数据表一种，报告页一种。

## 2. 布局

### 2.1 固定框架

```
项目名
（空行）
┌── 仪表盘 ──────────────────────────────┐
│ 当前配置                                │
│ 站点 ...                                │
│ 任务总览 ...                            │
└─────────────────────────────────────────┘
（空行）
面包屑
────────────────────────────────────────
（空行）
主体
（可选）状态槽：进度 / 操作结果
（空行，固定）
页脚：本页按键
```

- 页眉高度固定 2 行。
- 完整仪表盘只属于主菜单；其他页面压缩成一行上下文，避免 24 行终端里正文不足。
- 终端过矮时主菜单也使用单行上下文，正文始终保留最低可用行数。
- 状态槽固定在页脚上方；页脚前始终保留一行空行。
- 页码、筛选和已选数量属于正文的列表元信息，不得放列表底部，也不得成为全局状态。
- 页脚固定在最后一行；终端过窄时使用页面自己的紧凑写法，不能用通用页脚列出本页无效按键。

### 2.2 页面骨架

每个页面必须是以下顺序之一：

1. `summary`（可选）→ `sections` → `actions`。
2. `summary` → `body`（自定义行）→ `actions`。
3. 纯信息页：`message` 行 + 空行，不含 actions。

规则：

- **面包屑是页面标题**；正文不再重复画页面名。
- 实体名（模型名、收藏集名、版本名）可以作为正文第一行，使用 bold，**不再加第二条横线**。
- 正文最多一条横线：面包屑下方那条。`prompts.heading()` 只保留 bold 文本，不再画短横线。
- 分区标题统一为 `── 标题 ─────────`，使用 dim 色，占满可用宽度。
- 摘要使用 `label + 两空格 + value`，label 列按最长标签对齐，value 超宽裁剪。
- 报告页默认从摘要顶部开始；正文、可操作行和操作区是三个独立焦点，`Tab` 切换。
- 下载确认页固定显示摘要与操作按钮，中间列表独立滚动；开始按钮不得随长列表被裁掉。
- 列表元信息放在列表上方：`已选 12/50 | 筛选… | 第 1-10 项`。
- 操作区永远在最后，危险操作使用 `danger` 语义色。
- 状态槽由外壳固定在页脚上方；页面正文不得自行追加底部状态行。

### 2.3 缩进

- 框架左边距：宽度 ≥ 54 时为 2 列，否则 1 列。
- 菜单/表单行：`光标 + 空格 + 标签`，标签从第 2 列开始。
- 报告行：`两个空格 + 标签`；选中时用 `▸ ` 替换前两个空格，标签列不动。
- 分区标题从第 0 列开始（相对主体）。
- 摘要从第 2 列开始。

## 3. 列表

只允许两种变体。

### 3.1 MenuList / FormList

用于菜单、确认、设置、版本动作、任务列表。

```
▸ 下载                  下载模型或收藏集
  本地模型管理          按模型管理本地文件
```

- 光标：`▸`，非选中行用空格占位。
- 选中行标签加粗。
- 首尾循环。
- 翻页 10 行。
- `Home/End` 到首尾。
- 数字键只移动光标，不直接执行；执行统一用 Enter。

### 3.2 DataTable

用于选择器、下载计划、多选列表。

```
▸ [×]  1  模型名称          类型 · 底模 · 状态        1.2 GB
  [ ]  2  另一个模型        ...                       800 MB
```

- 整行反显表示光标。
- 第二列固定为勾选框。
- 列：光标、勾选、序号、名称、说明、大小。
- 夹紧不循环，避免长列表从末行跳回首行。
- 翻页使用自身 pageSize。
- 搜索、过滤、排序、`?` 帮助由选择器统一提供。

### 3.3 禁止

- 新增第三套列表渲染。
- 页面自己实现 `cursor <= 0 ? length - 1 : cursor - 1`。
- 页面自己计算名称列、大小列、详情列宽度。

## 4. 颜色与字符

### 4.1 语义色

| 令牌 | 用途 | 当前映射 |
|---|---|---|
| `color.text` | 普通文本 | 无样式 |
| `color.muted` | 次要说明、标签、边框 | `dim` |
| `color.accent` | 焦点、进度、信息 | `cyan` |
| `color.success` | 成功、登录态 | `green` |
| `color.warning` | 警告、排队、磁盘不足 | `yellow` |
| `color.danger` | 失败、错误、危险操作与危险确认 | `red` |
| `color.cursor` | 列表光标 | `cyan` |
| `color.selection` | 数据表选中行 | `reverse` |
| `color.progress` | 进度条 | `cyan` |
| `color.border` | 方框边框 | `dim` |

任务状态映射：

- `running` → `accent`
- `done` → `success`
- `queued` → `warning`
- `cancelled` → `muted`
- `failed` → `danger`

禁止：

- 流程层直接使用 `colors.red/green/...`；必须使用语义令牌。
- 新增 `colors.blue` / `colors.magenta` 的使用。

### 4.2 字符

所有展示字符必须来自 `layout.glyphs()` / `tokens.glyph`：

- 光标 `▸`，ASCII `>`
- 勾选 `[✓]` / `[ ]`，ASCII 降级为 `[x]` / `[ ]`
- 分隔 ` | `（TUI 内容、页脚提示与 TUI 硬编码统一；CLI/Web 不改）
- 项目符号 `·`（只用于列表项目，不充当分隔符）
- 失败 `!`
- 占位 `--`
- 方框与进度条随字符集降级

禁止在流程里写 `'·'`、`'!'`、`'--'`。

## 5. 键盘与页脚

### 5.1 全局键

- `↑↓`：移动；不再提供 `j/k`。
- `Home/End`：首尾。
- `PgUp/PgDn`：翻页。
- `Enter`：执行当前焦点动作，不是全局确认。
- `Esc`：返回直接父级或关闭覆盖层；回执页只回下载子菜单，不取消任务。
- `Tab`：页面内的区域焦点切换；报告页用于正文 / 可操作行 / 操作区。
- `Ctrl+T`：打开/关闭任务视图（全局覆盖层，主菜单同时提供「任务」入口）。
- `Ctrl+L`：打开会话日志（全局覆盖层，标题为“日志”）。
- `Ctrl+C`：退出；有任务运行时先请求取消。
- `?`：帮助；所有页面都应可用，并在帮助页列出上述全局键。

不使用 `Ctrl+M`：许多终端把它与回车编码为同一个控制字符，不能作为可靠的任务视图快捷键。
日志页只接受 `Esc` 关闭；单任务日志已移除。任务视图与日志页都不挂在主菜单下，
它们从任何页面都能用快捷键打开，属于全局覆盖层。

### 5.2 页脚

- 恰好一行。
- 只列这一页真的有动作的键。
- 不展示 `↑↓` / `j/k` 等通用移动键。
- 不自动附加全局键；`Tab`、`Ctrl+T`、`Ctrl+L` 是否出现由页面决定。
- 列不下时使用该页面的紧凑页脚，优先保留主操作，不能换成会撒谎的通用键位表。
- 工作台紧凑页脚按焦点变化：输入区保留 Add，列表保留选择/付费筛选，确认区保留 Confirm。
- `?` 作为动作键保留，用于查看全量键位（包括全局键）。
- 终端过窄时使用 `tui.hint.compact`，不截断词。
- `footerHints()` 不接受多行；页面返回多行会被丢弃。
- 下载计划页/确认页的页脚示例：
  `Tab 切换区域 | Enter 执行 | Esc 返回 | ? 帮助`。

### 5.3 面包屑与步骤

- 路径只表示位置，不表示动作：`主菜单 › 下载 › 下载模型`。
- 持久页面必须声明完整 `crumbPath`，不能只传 `title`；报告模型也必须带 `crumbPath`。
- 选择器、确认框、输入框、动作菜单、帮助页是临时界面，使用 `crumb: false` 或不进入路径。
- 选择器关闭后，调用方打开详情页时必须重新声明完整父级路径。
- 下载选择页的版本子页是多选模态：`Space` 勾选多个版本，`Enter` 应用（不勾选 = 不加入本次下载；全不勾 + `Enter` = 取消这一行、行仍留在列表里），`Esc` 放弃本次修改；它不新增面包屑，只保留来源路径与步骤。
- 同一模型的多个版本在工作台只占一行，版本名用 `/` 合并显示；确认时再展开为独立下载项。**这是断言级要求**：行的右列必须能看到版本名。
- 工作台行的右列顺序固定为 `版本清单 · 状态 · 基础模型 · 体积`（`rowLine()` 从尾部截断，版本名因此是窄终端下最后被丢的信息）。混合行的付费/限时版本名带后缀（见 5.4）。
- 报告页路径按来源补齐：模型报告 `本地模型管理 › ...`，收藏集报告 `本地收藏集管理 › ...`，体检报告 `设置 › ...`。
- 步骤表示当前流程进度：`[ 选择 | 确认 | 回执 ]`；路径与步骤分开，步骤不进入路径。
- 完整形式：`主菜单 › 下载 › 下载模型  [ 选择 | 确认 | 回执 ]`。
- 当前步骤高亮，已完成步骤 dim，未开始步骤更暗。
- 窄屏退化为 `步骤 2/3 确认`，不截断步骤词。
- 正文标题与父级同名时，不再 push 第二段；相邻两段不得相同。
- 任务视图与日志页是全局覆盖层，不进入主菜单路径；日志页标题为 `日志`。
- `Esc` 返回由流程定义，不由 `screen` 盲弹；创建任务页按 `Esc` 返回主菜单，任务继续运行。

## 5.4 付费与受限版本

- 访问状态按版本判断：`paidAccess` 优先于 `availability`；模型级 `hasActivePaidAccess` 不能锁住所有版本。
- 只在公开 API 有明确字段时显示“付费 / 付费至日期 / 早期访问 / 不可下载”，不展示不存在的价格。
- 行徽标汇总该行已知的全部版本：全付费 `[付费]`；混合 `[付费/免费]`；纯限时 `[限时访问]`；限时 + 免费 `[限时访问/免费]`；全免费不显示徽标（保持视觉安静）。
- 版本名后缀只在「行徽标无法说明该版本」时出现：

  | 行徽标 | 版本自身 | 后缀 | 例 |
  |---|---|---|---|
  | 无（全免费） | 免费 | 不带 | `v1.0` |
  | `[付费]`（全付费） | 付费 | 不带 | `[付费] Base_V2` |
  | `[付费/免费]` | 付费 | 带 | `[付费/免费] Base_V2（付费）` |
  | `[付费/免费]` | 限时付费 | 带（含日期） | `xxx（付费至 2026-11-15）` |
  | `[付费/免费]` | 免费 | 不带 | `Base_V2（付费）/SFT_V1` |

- 默认勾选只看本行的默认版本：免费则勾选，付费/限时不勾选；徽标是 `[付费/免费]` 但本行下的是免费版时，行是**已勾选**的。用户可显式勾选付费版本，但必须显示“需已有下载权限；不会购买或消耗 Buzz”。
- 同一模型多个基础模型时，行的“基础模型”显示去重列表（`MOSS Image / Krea 2`）；`b` 筛选按包含匹配，两种取值下该行都会出现。
- 无权限不计入网络失败，使用“需权限”计数，且不自动重试。

## 6. 反馈

所有反馈分四类：

| 场景 | 方式 |
|---|---|
| 字段校验错误 | 输入框下方的行内错误，修改前持续显示 |
| 页面级持久信息（付费、磁盘不足、会话缺失） | 正文顶部 banner |
| 操作进度 / 成功 / 失败 | 页脚上方状态槽；成功 3 秒，错误保留到下一次操作 |
| 过程细节 | `log`，按 `Ctrl+L` 查看 |

状态槽规则：

- 永远位于列表和固定操作区之后、页脚空行之前。
- 只显示一条信息；优先级为错误 > 进度 > 成功/提示。
- 使用具体动作，不显示泛化的“正在处理…”：例如“正在解析模型引用…”“正在加载版本…”。
- 本地搜索不产生进度状态，只更新列表元信息。
- 超过数秒的等待仍使用 `withSpinner`，但阶段写入状态槽，不再写面包屑。

禁止：空状态只写一行日志；错误只写日志不提示；状态显示在列表页码下面；正文与页脚之间没有空行。

## 7. 格式

统一使用 `tokens.format`：

| 函数 | 输出 |
|---|---|
| `format.date` | `YYYY-MM-DD` |
| `format.dateTime` | `YYYY-MM-DD HH:mm` |
| `format.dateTimeFull` | `YYYY-MM-DD HH:mm:ss` |
| `format.bytes` | `1.2 GB` |
| `format.duration` | `01:23` |
| `format.count` | 数字转字符串 |

未知值统一使用 `t('common.unknown')` 或 `tokens.glyph.placeholder`，不再混用 `-`、`--`、空字符串。

## 8. 响应式

断点：

- `narrow`：宽度 < 54，去掉边框、说明、次要列，页脚用紧凑写法。
- `compact`：54 ≤ 宽度 < 72，保留主要列，去掉次要列。
- `wide`：宽度 ≥ 72，完整布局。

降级顺序：

1. 去掉次要列（日期、路径、状态尾注）。
2. 去掉描述文字。
3. 去掉边框。
4. 页脚换紧凑写法。
5. 列表只保留名称与光标。

禁止每个页面自定义 `0.4`、`width - 30`、`64` 这类局部阈值；统一从 `tokens.breakpoint` 取。

## 9. 设计约束矩阵

| 方面 | 现状 | 目标 | 负责 Phase |
|---|---|---|---|
| 固定框架 | 强制 | 保持 | — |
| 页脚单行 | 强制 | 保持 | — |
| 页脚内容 | 混合全局/本页 | 只列本页动作键 | Phase 5 |
| 全局键 | `Tab`/`L` | `Ctrl+T`/`Ctrl+L` | Phase 3/5 |
| 页面标题/横线 | 多套 | 一套 | Phase 2 |
| 列表语法 | 4–6 套 | 2 种 | Phase 3 |
| 配色语义 | 调色板 | 语义令牌 | Phase 1 |
| 日期格式 | 4 种 | 1 套 | Phase 1 |
| 分隔符 | `·` / `\|` 混用 | TUI 内统一为 `\|` | Phase 1.5 |
| 空/加载/错误 | 4 种 | 1 套 | Phase 5 |
| `?` 帮助 | 部分 | 全部 | Phase 5 |
| 面包屑层级 | 有重复 | 无重复 | Phase 5 |
| 流程步骤 | 无 | `选择 \| 确认 \| 回执` | Phase 5 |
| 日志页 | 全局 `L` | `Ctrl+L` + 独立标题 `日志` | Phase 4/5 |
| 响应式断点 | 分散 | 3 档 | Phase 1/2 |
| 双路径等价 | 部分分叉 | 文档化 + 共享模型 | Phase 6 |

## 10. 评审清单

新增或修改页面时必须回答：

- 页面骨架是否用了 `page`（或 `report`/`picker`）？
- 是否只有一条横线？
- 是否使用了语义色和字符令牌？
- 分隔符是否统一为 ` | `？
- 是否只有一种列表变体？
- 页脚是否只有一行，且只列本页动作键？
- `?` 是否可用，并能查到 `Ctrl+T`/`Ctrl+L`/`Ctrl+C`？
- 流程步骤是否只在 `选择 | 确认 | 回执` 三态内？
- 日志页是否从 `Ctrl+L` 打开、标题为 `日志`、只接受 `Esc` 返回？
- 空状态、加载、错误是否走了统一反馈？
- 日期是否走了 `format`？
- 54×12 终端下是否不越界？
- 是否新增了 `screen.isActive()` 或直接终端写入？
